# Domain documentation

This repository uses one context. Read the root `CONTEXT.md` glossary before exploring or specifying domain behavior. Read relevant ADRs under `docs/adr/` if present; their absence is not a blocker. Create ADRs lazily only when a decision warrants one.

Use the glossary's canonical terms in specifications, issue titles, code, and tests. Keep the glossary limited to domain language, with product requirements and implementation details in separate documents. Surface contradictions with an existing ADR rather than silently overriding it.
